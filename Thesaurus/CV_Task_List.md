## Recommended cleanup & sync workflow (proposal - not yet actioned)

1. **Confirm CV-1 first** - everything else here assumes xlsx is the single hand-edited master and xml/csv are downstream exports. If that's wrong, this whole plan needs to flip.
2. **Adopt one normalized schema for every vocab CSV**, replacing the current wide "Hierarchy 1…8" columns with a tidy long-format table: one row per term, columns `Term (en)`, `Term (fr)`, `Term (ar)`, `Term (pt)`, `Alt label(s) (en)`, `Definition (en)`, `Definition (fr/ar/pt)`, `Parent term` (a single self-referencing column instead of N "Hierarchy N" columns - this is what actually models a SKOS broader/narrower tree, and makes every vocab file the same shape regardless of hierarchy depth), `Source`, and a `Status` column carrying the Legend's 6 values as text (fixes CV-9). This is the single biggest fix for the "dağınık" complaint - it turns 55 differently-shaped files into one predictable, diffable, scriptable shape. Needs the user's sign-off on the exact column list before any file is touched (same "don't invent a value/structure, flag for review" rule as the Metadata Template work).
3. **Resolve the known cruft before automating anything**: CV-3 (Activity vs Copy of 9.Activity), CV-4 (the 6 "TO BE DELETED" sheets), CV-8 (park the proposals sheet somewhere it won't be miscounted).
4. **Build one script** (in the gitignored `Scripts/` folder, matching the project convention) that: (a) exports every xlsx sheet into the new normalized CSV schema in one pass, reading tab/cell fill colour into the `Status` column instead of leaving it as Excel-only formatting; (b) diffs the xlsx-derived vocab name list against the xml collection name list and flags orphans in either direction (would have caught CV-3 and CV-6 automatically); (c) reports the xml-member-count vs csv-row-count gap per vocab as an upload-progress dashboard (would have produced CV-2's table automatically, and keeps it current instead of a one-time snapshot).
5. **Treat `xml/` as read-only** going forward - never hand-edit it; it should only ever be refreshed by re-exporting from Arches after an upload pass, so it stays a trustworthy mirror of "what's actually live."
