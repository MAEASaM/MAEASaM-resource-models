## Field schema (decided 2026-09-14)

The standard field list for every vocab CSV going forward is defined in **`Thesaurus/CV_Reference_Schema.csv`** (same style as `Reference Documents/template_attributes.csv`): `Term ID`, `Parent Term ID`, `Term (En/Fr/Ar/Pt)`, `Alt Label(s) (En)`, `Definition (En/Fr/Ar/Pt)`, `Source (En)`, `Status`. Long/tidy format (one row per term, unlimited hierarchy depth via `Parent Term ID`) instead of the old wide `Hierarchy 1…8` columns. No separate "Scope note" field - the user confirmed `Definition` alone covers it (2026-09-14), even though the underlying Arches XML happens to store this content under `skos:scopeNote`, not `skos:definition` - noted in the reference file so a future sync script maps it correctly.

**`Status` field - considered splitting, kept as one field (2026-09-14).** Measured actual usage of the xlsx's 6-value colour legend before deciding: 13/51 sheets use it at tab level, 30/51 sheets use it at cell (per-term) level, 627 individual cells total carry one of the 6 colours - but 2 of the 6 values (`NOT STARTED`, `COMPLETED`) are never used at cell level at all (0 cells each); the other 4 are used unevenly (`TO BE DELETED` 267 cells, `STARTED BUT REQUIRES ATTENTION` 224, `COMPLETED BUT REQUIRES SOME MODIFICATIONS` 102, `COMPLETED IN ARCHES` 34).
