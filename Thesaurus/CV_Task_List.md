## Field schema (decided 2026-09-14)

The standard field list for every vocab CSV going forward is defined in **`Thesaurus/CV_Reference_Schema.csv`** (same style as `Reference Documents/template_attributes.csv`): `Term ID`, `Parent Term ID`, `Term (En/Fr/Ar/Pt)`, `Alt Label(s) (En)`, `Definition (En/Fr/Ar/Pt)`, `Source (En)`, `Status`. Long/tidy format (one row per term, unlimited hierarchy depth via `Parent Term ID`) instead of the old wide `Hierarchy 1…8` columns. No separate "Scope note" field - the user confirmed `Definition` alone covers it (2026-09-14), even though the underlying Arches XML happens to store this content under `skos:scopeNote`, not `skos:definition` - noted in the reference file so a future sync script maps it correctly.

**`Status` field - considered splitting, kept as one field (2026-09-14).** Measured actual usage of the xlsx's 6-value colour legend before deciding: 13/51 sheets use it at tab level, 30/51 sheets use it at cell (per-term) level, 627 individual cells total carry one of the 6 colours - but 2 of the 6 values (`NOT STARTED`, `COMPLETED`) are never used at cell level at all (0 cells each); the other 4 are used unevenly (`TO BE DELETED` 267 cells, `STARTED BUT REQUIRES ATTENTION` 224, `COMPLETED BUT REQUIRES SOME MODIFICATIONS` 102, `COMPLETED IN ARCHES` 34). A two-axis redesign (`Review Status`: NOT STARTED/IN PROGRESS/NEEDS REVISION/APPROVED/TO BE DELETED, separate from `Arches Status`: NOT UPLOADED/UPLOADED/RETIRED - would have cleanly resolved CV-4's "TO BE DELETED but also live in Arches" contradiction) was proposed and would have been a lossless 1:1 (or 1:2 for `COMPLETED IN ARCHES`) remapping of the existing 627 marked cells. **User's call: given usage is real but moderate, keep the single `Status` field with its original 6 values for now rather than disrupt the existing convention; revisit (possibly the two-axis split, possibly just adding values) later if it becomes a real friction point.** Nothing needs to change in `CV_Reference_Schema.csv` as a result of this discussion - it already only ever had the single-field version.

## Recommended cleanup & sync workflow

1. **Confirm CV-1 first** - everything else here assumes xlsx is the single hand-edited master and xml/csv are downstream exports. If that's wrong, this whole plan needs to flip.
2. ~~Adopt one normalized schema~~ **Done 2026-09-14** - see `CV_Reference_Schema.csv` and the Field schema section above.
3. **Resolve the known cruft before automating anything**: CV-3 (Activity vs Copy of 9.Activity), CV-4 (the 6 "TO BE DELETED" sheets), CV-8 (park the proposals sheet somewhere it won't be miscounted), CV-10 (get a consistent xml export pair).
4. **Migrate vocab CSVs to the new schema model-by-model** (CV-11), prioritized by whichever resource model the user is actively standardizing, rather than all 55 at once - keeps each batch reviewable and tied to real, immediate use.
5. **Build one script** (in the gitignored `Scripts/` folder, matching the project convention) that: (a) exports every xlsx sheet into the new normalized CSV schema in one pass, reading tab/cell fill colour into the `Status` column instead of leaving it as Excel-only formatting; (b) diffs the xlsx-derived vocab name list against the xml collection name list and flags orphans in either direction (would have caught CV-3 and CV-6 automatically); (c) reports the xml-member-count vs csv-row-count gap per vocab as an upload-progress dashboard (would have produced CV-2's table automatically, and keeps it current instead of a one-time snapshot). Not started yet - the manual pilot (CV-11) is deliberately first, to validate the schema before automating it.
6. **Treat `xml/` as read-only** going forward - never hand-edit it; it should only ever be refreshed by re-exporting from Arches after an upload pass, so it stays a trustworthy mirror of "what's actually live." (CV-10 means it's currently not even a trustworthy mirror of itself.)
