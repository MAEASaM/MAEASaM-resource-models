Copyright & Access Ledger

Who may use a resource, under what licence, and how to cite it. RS, Chronology and Map already agree field‑for‑field in their CSVs (settled back on 2026‑09‑02, Task_List #38). Coverage across the other four models is now understood too: Actor deliberately has none (not rights‑bearing content), Info's single field is a correct verbatim Zotero import, and Admin and Grid both need the group added — Admin because its boundary data is externally sourced, Grid because MAEASaM's own output may still be deposited or shared externally later. What's left is implementation: JSON catching up with each CSV, and adding the two new groups.

Confirmed 2026‑09‑10: Admin's administrative boundary data is sourced externally (government/GIS institution) — genuinely rights‑bearing content, should get the same 5‑field group as RS/Chronology/Map. Not yet implemented (Task_List #60).

Grid Real gap (reversed call)

No Copyright & Access fields exist yet in Grid_MetadataTemplate.csv or Grid.json.

Reversed 2026‑09‑10: originally judged unnecessary since Grid is MAEASaM's own output, not externally‑licensed content. But "we produced it ourselves" isn't the right test — an unlicensed resource defaults to "all rights reserved," blocking reuse even when reuse is intended. There's a real possibility this data gets deposited in an external archive or shared with other teams later, so the group is being added proactively now rather than retrofitted afterward. Same 5‑field pattern as Admin. Not yet implemented (Task_List #62).
