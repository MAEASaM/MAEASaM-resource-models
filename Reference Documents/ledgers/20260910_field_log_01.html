A chronological record of decisions actually made during standardization — kept separate from the open-issue tracker. Still-open questions live in Reminders.md and the Inconsistencies tab, not here.

2026‑09‑09
  • Recorder must link to an Actor record everywhere (Resource-Instance-List, not plain text). RS and Info already did; extended to Grid, Map and Chronology (Chronology's CSV had already specified it — its JSON was a bug, now fixed).
  • Canonical group names adopted (initial pick, later revised on 09‑10) for the two “system metadata” clusters, replacing five inconsistent variants found across the seven models: Recording details — Recorder, Comment, Resource created at; Upload details — Uploader name, Upload date, Resource last modified at.
  • Recorder's Cardinality standardized to 1..n across all five models that carry it (RS, Info, Chronology, Grid, Map) — one card, multiple people credited via the widget's own multi-select, rather than repeating the card. Also resolved Info's pre-existing Mandatory + 0..1 contradiction.
  • Grid's “Number of maps” added as a node (mirroring “Number of sites” / “Number of remote sensing sites” — no data-entry widget, populated externally), isolated on its own branch (grid-number-of-maps-node) pending Arches import testing, rather than merged directly.
2026‑09‑10
  • Final field names settled (resolves the “still open” naming question from 09‑09): Recorder (was already the majority form; RS's “Name of the recorder” and Chronology's “Name of recorder” renamed to match) · Created at (was “Resource created at” / Chronology's “Resource creation at”) · Comment (unchanged) · Uploader (was “Uploader name”) · Uploaded at (was “Upload date”) · Last modified at (was “Resource last modified at” / Chronology's “Resource modified at”).
  • Group name for the second cluster revised to “Uploading details”, superseding 09‑09's “Upload details” pick. Final pair: Recording details (the cataloguer's side) / Uploading details (the Arches ingestor's side).
  • Uploader now also links to an Actor record in Actor, Admin, Grid and Map — both roles are people who should be represented in the Actor model. Consequence accepted: Uploader's Operational Info changes from Auto‑Populated to Foreign Key, since Arches can't resolve a login session to an Actor record without custom development. Cardinality kept at 1 (not 1..n like Recorder) — a single ingestor per upload.
  • Renamed all multi-language widget labels' English text to match (Map's Arabic/French/Portuguese translations left untouched).
  • “Created at” clarified as manually entered, not a system timestamp — resolving whether Created at / Uploaded at are the same event: they're not. Created at records when the cataloguer produced the content (manual); Uploaded at records when the record entered Arches (genuinely automatic). Operational Info changed from Auto‑Populated to N/A across RS, Info, Chronology, Grid and Map.
  • Copyright & Access group coverage clarified — not every model should carry it, and that's correct, not a gap: Actor gets no group by design (not rights-bearing content); Grid initially called no-group, reversed later the same day (below); Info's single merged Copyright field stays as-is (a verbatim Zotero import, not MAEASaM's own vocabulary); Admin is the one real gap — externally-sourced boundary data, needs the full five-field group.
  • Ledger files moved from Scripts/exports/ (gitignored) to Reference Documents/ledgers/ (tracked in git) — presentation material for the team/management, not local scratch work.
  • Grid's “no Copyright & Access” call reversed — it should get the full five-field group after all, matching Admin. Reasoning: “we produced it ourselves” isn't the right test for whether a licence is needed — an unlicensed resource defaults to “all rights reserved” in most jurisdictions, blocking reuse even when reuse is intended. There's a real possibility MAEASaM's grid data gets deposited in an external archive (ADS/tDAR/Zenodo-type) or shared with other teams later — added proactively rather than retrofitted.
  • Both additions implemented the same day: Licence, Access level, Rights holder, Rights Notes and Preferred Citation added to Admin and Grid's CSV/JSON, matching RS/Chronology/Map field-for-field. CIDOC CRM Node Class left blank in both, consistent with the others — that classification stays Package 2's call.
  • Canonical field/group order established for all seven templates: Copyright & Access → Recording details → Uploading details, always last, in that order. Within each group the field order is fixed too: Licence/Access level/Rights holder/Rights Notes/Preferred Citation; Recorder/Comment/Created at; Uploader/Uploaded at/Last modified at.
  • Every model completed to the full pattern, not just reordered — confirmed with the user before applying, since the supplied target order (20260910_All_MetadataTemplates_01.xlsx) turned out to add fields, not just reorder them: RS gained Comment/Uploader/Uploaded at; Actor and Admin gained Recorder/Created at; Chronology and Info gained Uploader/Uploaded at; Nodes modified intentionally removed from RS and Chronology.
  • Actor's and Chronology's pre-existing Comment fields were relocated into the new Recording details group, not duplicated — the supplied xlsx had in fact introduced a second, literal duplicate Comment node in both, caught before applying.
  • As a side effect of extracting Chronology's old Comment column, Editorial note briefly lost its Contextual information group label (a forward-fill artifact) — caught by the consistency checker and corrected before this was reported as done.
  • Also corrected in passing: the semantic container node behind the Uploading details card was still internally named “Arches upload details” in Actor, Admin, Grid and Map (the 09‑09 rename only touched the card's own label) — fixed everywhere. RS's “Copyright/access” card label capitalization also fixed.
  • Definitions for Recorder, Comment, Created at, Uploader, Uploaded at and Last modified at unified to one canonical sentence per field across all seven models — including two lingering “grid square instance” copy-paste-bug copies in Admin's and Grid's Uploaded at / Last modified at, missed when Uploader was fixed on 09‑09. New wording drops the “This node records…” framing for direct phrasing, keeping Arches-internal (“node”) language out of user-facing text. The same “This node” phrasing exists in ~34 other definitions project-wide, mostly RS's own established style — left alone as a separate, bigger terminology decision (Task #65).
  • Fixed in the same pass: Info's Recorder Collection/Instructions said “Actor Model (rm)” instead of “Actor (rm)” — inconsistent with every other model and with the resource model's real name.
  • RS.json's Copyright & Access group deliberately left unrepaired (still has stale pre-09‑02 node names/types, missing Licence and Rights holder) — fixing it means correcting existing stale nodes, not just adding new ones, bundled with the already-tracked RS.json drift (Task #57/#61) rather than attempted piecemeal here.

Still open — not decided yet

  • Whether Uploader's now-manual entry needs a future Arches function to auto-resolve the logged-in user to their Actor record (restoring some form of auto-population) — flagged 2026‑09‑10, not scoped yet.

Resource version control, Cataloguer & Admin roles

Before

No single model's field set covers every concept in use elsewhere — adopting any one wholesale means either dropping a concept some models rely on, or adding concepts to models that lack it. Grid and Map are the only two carrying both Recorder and Uploader side by side.

Naming varies per concept — Recorder: “Recorder” / “Name of recorder” / “Name of the recorder”; Created at: “Resource created at” / “Resource creation at”; Last modified: “Resource last modified at” / “Resource modified at”; Uploader name capitalization differs (Actor/Admin/Grid vs Map).
Recorder modeled two different ways — RS/Info link it to an Actor record; Grid/Map store plain free text; Chronology's CSV specified Resource-Instance-List but its JSON had plain string — a genuine mismatch, not a design choice.
Group naming varies — “Resource version control” / “Arches upload details” / “Recording details” / “Recording Details” / “Uploader Details” / a group containing only “Recorder”.
Copy-paste in definitions — Admin's Uploader name/Upload date/Resource last modified at, and Map's Uploader Name, all describe “the grid square instance,” copied verbatim from Grid, with two carried-over typos (“uplaoded”, “ot Arches”).
Map's Recorder definition is a single word (“Cataloguer”) where every other model has a full sentence.
Necessity/Cardinality drift — Info's Recorder is Mandatory but Cardinality 0..1; Info's Last modified at is Strongly recommended vs Mandatory in RS/Chronology; Map's Recorder allows 1..n while every other model is single-valued; Map's Comment is Mandatory, Grid's is Optional.
✓ After
  1. Field names standardized: Recorder, Created at, Comment, Uploader, Uploaded at, Last modified at.
  2. Group names standardized: Recording details (Recorder, Comment, Created at) and Uploading details (Uploader, Uploaded at, Last modified at).
  3. Both Recorder and Uploader link to an Actor record everywhere they appear — Uploader's Auto‑Populated traded for Foreign Key as a consequence.
  4. Recorder's Cardinality standardized to 1..n; Uploader kept at 1.
  5. Created at clarified as manually entered, distinct from Uploaded at's genuine auto-population. Operational Info corrected Auto‑Populated → N/A across RS, Info, Chronology, Grid and Map.
Not yet decided: whether every model should carry both concepts (RS/Chronology/Info still lack Uploading details; Actor/Admin still lack Recording details) — out of scope for this round. Also open: correct wording for Admin's copy-pasted “grid square” definitions.

Topic 02

Before

Three open questions: should Actor/Admin/Grid carry the group at all, is Info's reduced field correct or a gap, and does each model's JSON match its own settled CSV.

✓ After
  1. Actor correctly has no Copyright/Access group — a person/org record isn't rights-bearing content. Deliberate, not a gap.
  2. Info's single merged Copyright field is also correct as-is — a verbatim Zotero import, not MAEASaM's own vocabulary. Not expanded to the 5-field pattern.
  3. Admin and Grid both got the full 5-field group, matching RS/Chronology/Map: Admin because its boundary data is externally sourced; Grid because “we produced it ourselves” isn't the right test — an unlicensed resource defaults to all-rights-reserved, and deposit/sharing is a real future possibility.
Still open (implementation only): bring RS.json and Chronology.json's structure up to date with their own CSVs (group entirely missing from both), and sync Map.json's CIDOC classes, descriptions and group casing (Task #61).
